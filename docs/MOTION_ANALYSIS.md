# CRF search and sample motion

Auto uses ab-av1 **crf-search**, not auto-encode. ab-av1 chooses the quality settings to try. Archiver's current single Auto target remains mean VMAF 97 with the selected codec/method; software uses CRF, while supported hardware uses its encoder-specific quality control. Analysis uses --max-encoded-percent 10000: a very high ceiling, not mathematical infinity. This separates measuring a target-quality configuration from deciding whether it saves enough space to encode.

Every completed search attempt retains its CRF/quality setting, mean sample quality score, predicted size/percentage, and predicted full encoding time. The UI exposes a search-attempt table. crf-search-measurements.json and the verbose log remain beside the source, including when a later attempt or target search fails. A larger configuration can be reported as a valid quality result; output size is informational, and final output must still pass the sampled quality checks. Current Auto uses XPSNR 38 dB.

Before the quality search, FFmpeg's **vmafmotion** filter measures each requested sample window once at source resolution and timing. It does not analyze the preview proxy. A trim before the motion filter bounds the score to the requested duration. No resizing, frame-rate reduction, computer vision, or optical flow is used. Mean, 95th percentile, peak, and frame count are recorded; the filter's raw per-frame text files and motion-summary.json remain in the test folder. The first frame's filter score is zero because no preceding sample frame exists; it is included in the summary as reported by the filter. A single-frame sample cannot establish temporal activity.

These are raw frame-change scores, not percentages, speed, object motion, or a visual-quality score. Camera movement, scene cuts, lighting, noise and frame rate can affect them. Larger mean values indicate more frame change under comparable processing conditions. Labels are **Lower within test**, **Middle within test**, **Higher within test**, **Similar within test**, or **Single sample**. They compare tested clips only; they are not calibrated universal low/moderate/high thresholds.

The sample cards show mean motion. Expand Sample motion measurements for the full table. Missing or failed motion measurements are shown as unavailable and do not invalidate successful CRF results. Motion analysis adds one decoding/filter pass per requested window, rather than a new pass for every CRF trial. It is serial with the quality search and cancellable. Motion data is collected and saved first, so a failed quality search does not discard it.

Sampling remains Archiver's current distributed short windows (or full input for short clips), not the random eight-second/concatenated-reference proposal from the shared discussion. Source-side exact requested windows can differ from ab-av1's stream-copied sample boundaries at keyframes; scores are explicitly described as requested-window measurements. Random sample preparation, multi-codec/multi-target analysis and a PySide interface have not been introduced by this update.

Primary reference: [FFmpeg vmafmotion documentation](https://ffmpeg.org/ffmpeg-filters.html#vmafmotion).
